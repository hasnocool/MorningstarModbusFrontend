# v0.5.1 Capability-aware metric coverage

MorningstarModbusFrontend v0.5.1 improves how the site pages present source-backed, derived, unsupported, conflicting, and currently unavailable measurements.

## Problem

The backend deliberately keeps unsupported measurements unknown instead of inventing values. The frontend previously collapsed those different states into the same `— / empty` presentation, making missing instrumentation look like broken telemetry. The Power Flow page also looked for solar-generation evidence under the wrong response key, so a valid `solar_input_power_w` reading could appear in the balance section while the Solar panel simultaneously claimed no source-backed values were available.

## Changes

### Capability-aware empty states

Normalized readings now distinguish:

- observed / partial / derived values;
- conflicting authoritative sources;
- hardware that does not expose the normalized metric (`expected_contributors: 0`);
- hardware that should expose the metric but has no current observation (`expected_contributors > 0`, no contributors);
- ledger fields that are unavailable for a backend-provided reason.

Unavailable readings are moved into an explanatory disclosure instead of filling the primary grid with dashes. Backend `reason`, `source_metric`, and `formula` metadata remain visible.

### Solar power-flow fix

The Solar / Generation panel now renders the backend `sources` section, including `solar_input_power_w`, rather than checking only legacy/nonexistent `solar`, `generation`, or `controllers` keys.

When the TriStar MPPT supplies `input_power_reported`, the balance section warns that conversion efficiency is based on Morningstar's controller-reported PV input estimate and should be interpreted as approximate rather than a precision efficiency measurement.

### More normalized telemetry on Site Overview

The Site Overview retains its four primary operating cards and adds an Additional site metrics panel so other normalized values—such as array voltage, battery temperature, charge state, energy counters, faults, and alarms—can appear when the backend has evidence for them.

### Exact unit conversion

When a source-backed `daily_charge_wh` counter is present, the Energy page also exposes an exact derived kWh display view (`daily_charge_wh / 1000`). This does not claim a second native controller counter; provenance and the conversion formula are displayed.

## Safety and semantics

The frontend still does not infer battery SOC, battery net current, load consumption, inverter power, generator energy, discharge energy, or other measurements that require additional instrumentation. No Modbus writes or controller configuration changes are introduced.
